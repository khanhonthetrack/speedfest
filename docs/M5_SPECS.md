# M5 visual upgrade: specs for the three parallel sessions

Owner request (2026-10-15, TRANSCRIPT): the graphics are "kinda trivial" and the menus look "very
mobiley and boring". Path tracing is parked (docs/RENDERING.md). Focus on **real art and lighting
on mainline Godot 4.7.2** (RENDERING §3 item 1) and an **NFSU2-style 3D front end** (RENDERING §4).

Three sessions work in parallel, each on its own branch, and the orchestrator merges them into
`main`. First attempt (orchestrator #3, ~08:35 UTC) used local worktree agents whose work never
reached GitHub and was lost. **So: commit and push to your branch after every meaningful step
(at least every ~30–45 min of work), not just at the end.**

## Rules for every M5 session

1. Read `CLAUDE.md`, `docs/HANDOFF.md`, `docs/ARCHITECTURE.md`, `docs/DESIGN.md` (§3.2, §4, §6, §7),
   `docs/RENDERING.md`, then your module doc(s) below. Set up the environment per `CLAUDE.md`.
2. Branch: create `visual/<key>` from `origin/main` and push only there (`git push -u origin visual/<key>`).
   Never push to `main`. If `main` moves, `git merge origin/main` into your branch (no rebase).
3. Only edit the files you own (tables below). If you need something outside them, write it down in
   your module doc under "Requests for the integrator" with the exact change, and work around it.
4. **Both renderers must keep working.** Forward+ is the desktop/console target and should look
   great at High/Ultra. Compatibility (web, quality 1 by default) must look **at least as good as
   today** and must not get slower: keep a race scene ≤ ~400 draw calls on compat (`perf_probe`),
   no new per-frame CPU cost on web, and no shader features that compat lacks (check with
   `--compat` screenshots). Branch on `Settings.is_compat()` / `Settings.quality`.
5. **Asset rules.** Only CC0 assets (ambientCG, Poly Haven) or assets generated by scripts in this
   repo. List every file in `docs/ASSETS.md` (source URL, license). Keep generator scripts under
   `tools/`. Desktop-only, large assets (2K+ textures, HDRIs) go under `game/assets/hd/**`, which the
   Web export must exclude (the integrator adds `assets/hd/*` to the Web preset's `exclude_filter`;
   your code must fall back cleanly when `ResourceLoader.exists()` is false). Web-shipped assets:
   ≤ ~10 MB added to the web `.pck` per session. Prefer 1K textures, JPG/PNG/WebP, VRAM-compressed import.
6. Blender is available as a Python module (all sessions may use it):
   `python3 -m venv /opt/bpyenv && /opt/bpyenv/bin/pip install bpy` (wheel ≈ 350 MB; headless Cycles
   and EEVEE renders and glTF export work). Commit the `.py` generators; commit generated `.glb`
   outputs too (so other agents don't need Blender), with their `.import` files.
7. Verify with your eyes: screenshots on **both** renderers (`tools/run_scene.sh ... --shot=`), at
   quality 1 (compat) and quality 3 (Forward+). Save a before/after set and describe it in your doc.
   `tools/check_scripts.sh` → `SCRIPT_ERRORS=0`, your module tests pass, and before your final push
   `tools/integration/check_all.sh --quick` → `CHECK_ALL PASS`.
8. Keep public APIs from `docs/ARCHITECTURE.md`. API additions go in your module doc.
9. Document as you go in your module doc: a **"Handoff"** section at the top (state, what's left,
   how to verify) kept current at every push, so another agent can continue if you stop.
10. Don't re-export `server/public` (tonight's web build). The integrator does that after merging.
11. Commit messages: `<key>: <what>` (e.g. `cars: blender kaze body with part variants`).

## visual/cars: hero car models (key `cars`)

**Owns:** `game/cars/visual/**`, `game/shaders/car_*.gdshader`, `game/tests/visual/**`,
`game/assets/cars/**`, `game/assets/hd/cars/**`, `tools/blender/cars/**`, `docs/modules/visuals.md`.

Goal: the three cars look like real NFSU2-era tuner cars (smooth subdivided bodies, panel gaps,
real lamp lenses, glass, chrome, tires with sidewalls), not faceted lofts.

- Model `kaze` (JDM coupe), `brute` (American muscle) and `veloce` (mid-engine supercar) in
  **Blender via Python scripts** (`tools/blender/cars/*.py`): subdivision, bevels, booleans,
  shrinkwrap and so on. Original designs, no real brands. Export glTF (`.glb`).
- **Same `CarVisual` API** (ARCHITECTURE "CarVisual" plus docs/modules/visuals.md additions):
  `build`, `apply_style`, `set_wheel_state`, `set_lights`, `set_nitro`, `set_ghost`,
  `set_underglow_enabled`, `set_headlights_real`, `get_exhaust_points`, `get_wheel_transform`,
  the static `night_rim`, and `underglow_light_allowed`. Wheel centers, radius and width must match
  `CarDefs` geometry exactly (physics depends on them). Origin and ground conventions are unchanged.
- **All customization slots still work:** hood 0..3 (plus carbon), front 0..2, rear 0..2, skirts
  0..2, spoiler 0..4, rims 0..4 (5 designs, `rim_color`, caliper color), paint plus finish
  (gloss/metallic/pearl/matte/chrome), accent, liveries (in car-local space as today, or UV-based),
  window tint, headlight color, underglow modes, ride height, plate text. Each part variant is a
  separate mesh node toggled by style, or a shared mesh plus a variant mesh; keep part switches cheap.
- **Materials:** car paint with clearcoat and flake on Forward+ (keep `car_paint.gdshader` or
  extend it), proper tinted glass (reflective, see-through to an interior), chrome, black trim,
  rubber with sidewall lettering, carbon weave, emissive lamp lenses with reflector detail
  (head/tail/brake/reverse driven by `set_lights`), and brake discs.
- **Budgets:** Forward+ LOD0 ≤ ~60k triangles per car including wheels. Godot's import-time mesh
  LODs (or explicit LODs) for distance and remote cars. On compat, use the LODs (≤ ~20k at quality
  ≤ 1) and ≤ ~10 draw calls per car. Ghost mode must keep working on both renderers.
- **Fallback:** keep the procedural builder as a fallback when a `.glb` is missing, until the
  integrator removes it.
- **Verify:** `tests/visual/test_build.tscn` (update it to the new models), showcase screenshots of
  each car with several part combos (Forward+ q3 and compat q1), a race screenshot per track, the
  garage (`res://ui/garage.tscn`), and the PB ghost. Note triangle and draw-call counts in the doc.

## visual/world: lighting, materials, reflections (key `world`)

**Owns:** `game/tracks/scenery/**`, `game/shaders/env_*.gdshader`, `game/shaders/road*.gdshader`,
`game/shaders/track_*.gdshader`, the **material functions only** in `game/tracks/track_builder.gd`
(`material()`, `road_material()`, `_neon_color()`, and the parameters passed to `shader_material()`;
no geometry, collision or layout changes), the visual weather files `game/weather/weather_fx.gd`,
`game/weather/water_spray.gd`, `game/shaders/track_puddle.gdshader` (not `weather.gd` or
`track_surface.gd`, which hold grip logic), `Settings.tune_environment()`, `tune_sun()` and
`light_budget()` in `game/autoload/settings.gd` (only those three functions),
`game/assets/textures/**`, `game/assets/hd/textures/**`, `game/assets/hd/hdri/**`,
`game/tests/scenery/**`, `tools/textures/**`, `docs/modules/scenery.md`.

Goal: NFSU2-at-night quality: wet roads that reflect neon and headlights, puddles that mirror the
city, textured asphalt and concrete, buildings with depth, atmospheric fog and light shafts.

- **Reflections:** `ReflectionProbe`s placed per track sector (box-projected along the road),
  SSR tuned for the wet road on High/Ultra, and a wet/puddle road response that actually shows
  reflections (roughness and normal from the weather wetness and puddle masks). Compat: keep a
  cheap fake (sky/probe-based) reflection; no SSR there.
- **PBR textures (CC0):** asphalt (with lane paint kept procedural or as a decal layer),
  concrete for decks/walls/pillars, metal for barriers and gantries, rock or terrain for coast.
  Triplanar or UV mapping. 1K for everything shipped to web, optional 2K under `assets/hd/`.
- **Buildings:** facades with depth: interior-mapped or parallax windows (lit rooms at night,
  curtains, variety), ledges and pilasters, rooftop clutter (AC units, water tanks, antennas, neon
  signs), storefront levels at street height for downtown. Keep draw calls in check
  (MultiMesh, batching via `scenery_batches.gd`).
- **Sky and atmosphere:** HDRI or better procedural skies per theme (night city, stadium night,
  coast sunset), volumetric fog with light shafts from street lamps and stadium floodlights on
  Ultra, height fog, and SDFGI or baked-looking ambient on Ultra.
- **Grade and post:** a per-theme color grade (Environment adjustments plus a LUT if useful), glow
  tuned for neon, optional lens dirt, and tonemap (AgX or Filmic). Quality presets: desktop High and
  Ultra look great, Medium is the web default (compat), and Low is for weak devices.
- **Weather visuals:** rain streaks and splashes, wet sheen everywhere in rain/storm, reflective
  puddles (the owner's showcase: "Ray path tracing looks good for puddles"), lightning lighting the
  clouds. Puddle *positions and grip* stay as the weather module made them.
- **Verify:** `tests/scenery/*` and `tests/weather/*` pass, perf_probe on compat q1 per track (draw
  calls ≤ ~400, note before/after), and before/after screenshots of every track in dry and storm on
  both renderers.

## visual/frontend: NFSU2-style 3D front end (key `frontend`)

**Owns:** `game/ui/main_menu.*`, `game/ui/garage.*`, `game/ui/track_select.*`,
`game/ui/settings_menu.*`, `game/ui/online_lobby.*` (look and layout only; keep its networking
behavior and the lobby test hooks), `game/ui/menu/**`, `game/ui/frontend/**` (new),
`game/ui/ui_theme.gd`, `game/tests/ui_menus/**`, `docs/modules/ui_menus.md`.

Goal: replace the flat chip-grid menus with an **NFSU2-style 3D tuner garage that *is* the menu**.

- One lit 3D garage scene built in code: car center stage on a turntable or lift, glossy concrete
  floor, garage door, tool walls, neon signage, a paint booth, a dyno, a wheel rack, a monitor wall
  for online and track select. The **camera dollies between stations** instead of switching screens
  (main menu → car select → paint booth → body shop → wheels → neon and lights → dyno/tuning →
  online board → track select).
- NFSU2-style UI over it: big skewed Orbitron type, vertical lists on the left with the selected
  item enlarged and glowing, part carousels along the bottom, stat bars, a few angular panels, no
  chip grids. Diegetic touches: menu labels as neon signs, wall screens. Music-synced pulses
  optional.
- **Controller-first** (Switch target): every screen fully usable with d-pad/stick, A/B, L/R
  (tabs), and keyboard (arrows, Enter, Esc, Q/E). Mouse also works.
- Keep everything that works today: name entry, solo track select (track, weather chips, PB per
  weather), online lobby flow (connect, rooms, chat, host picks track/length/weather, round
  auto-join from the garage), settings (graphics quality and so on), garage tuning and styling with
  `Profile` saving, and `Game` scene flow. Keep or update the tests in `game/tests/ui_menus/**`
  (`garage_test`, `nav_test`, `lobby_fake_test`, `lobby_smoke.sh`) so they cover the new UI.
- Web (compat, q1): the same front end, scaled down (fewer lights, no volumetrics, simpler floor
  reflections), and it must stay responsive. 720p and 1080p layouts, and 16:9 handheld-friendly text sizes.
- Use `CarVisual` only through its API (the cars session is swapping the model behind it).
- **Verify:** `game/tests/ui_menus/screenshots.sh` (extend it per station), nav/garage/lobby tests,
  and a short write-up of the station flow with screenshots in the doc.
